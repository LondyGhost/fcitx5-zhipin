# Linux 智能 ABC 输入法

本项目计划实现一个**独立的 fcitx5 输入法引擎**，用于 ABC 风格的字母暂存、候选确认和中文上屏。它不是 fcitx5-rime 前端补丁，也不依赖 XIM、XTest 或 xdotool。Wayland 输入法协议由 fcitx5 框架负责，应用通过 fcitx5 原生输入法通路接收预编辑和提交文本。

## 项目约定

- 项目及所有源码、脚本、测试、日志、文档和可交接构建产物的归档位置：`D:\workbuddy\linux智能ABC`。
- 最终 Linux 构建、部署和 Wayland 验收目标：`192.168.1.250:47672`，账户 `londy`。凭据只保存在被忽略的本地文件，不得写进 Git、日志或命令输出。
- 不修改 `/opt`，不覆盖系统 `/usr` 下的输入法、fcitx5、librime 文件。优先部署至用户目录或项目隔离前缀。
- 外网命令行访问按环境要求使用 `127.0.0.1:7897` 代理。
- 详细架构见 [`docs/独立引擎整体方案.md`](docs/独立引擎整体方案.md)，并行任务边界见 [`docs/并行开发任务拆分.md`](docs/并行开发任务拆分.md)。
- 可单独分配的任务说明位于 [`tasks/README.md`](tasks/README.md)；每个任务有独立 Markdown，可直接发给对应参与者。
- 独立任务最终由同一位集成验收负责人汇总验收，标准见 [`docs/独立任务验收标准.md`](docs/独立任务验收标准.md)。

## 当前状态

当前阶段为方案和接口冻结，独立引擎实现尚未开始。已有 librime/abc_buffer 试验仅作行为参考及词库验证基线；其缓冲不可见问题是改为独立引擎的原因。不要将旧插件作为最终输入前端方案。

## 目录

- `source/`：引擎及工具源代码
- `tests/`：单元、集成、兼容性和手工验收用例
- `scripts/`：构建、部署、采集诊断脚本
- `deploy/`：用户级安装及回滚模板
- `artifacts/`：经审查可交接的构建产物
- `logs/`：脱敏后的构建与验收日志
