# 独立任务交付与统一验收标准

## 1. 验收原则

所有并行开发任务（A0–A5）各自完成自测并提交交付材料；**最终汇总验收由一位指定的集成验收负责人统一完成**。该负责人应是未承担被验收模块主要实现的人；如人员规模不允许，须明确披露其实现与验收范围，并安排另一位人员复核关键验收结论。模块作者的“自测通过”不等于任务通过验收。

集成验收负责人对接收标准、跨模块兼容、端到端行为、目标机部署、安全边界、缺陷关闭和最终结论负责。每个任务只能有一个明确结论：`通过`、`有条件通过`或`不通过`；结论、依据及遗留问题写入 `docs/验收记录.md`。不得以口头确认替代记录。

## 2. 各任务交付门槛

每个任务提交验收前必须提供：

1. 任务编号、负责人、提交号/分支、接口契约版本。
2. 变更文件清单；确认未越过 `docs/并行开发任务拆分.md` 的文件所有权边界，例外须有集成负责人书面批准。
3. 可复现的构建和测试命令、完整结果及运行环境；失败项不得隐藏或只报“通过”。
4. 模块说明、输入/输出、错误处理、已知限制和下游集成方式。
5. 依赖/许可证和测试数据来源说明；不得携带未授权词库、真实用户输入、凭据或 token。
6. 任何生成产物的来源、版本、校验值和归档路径；日志须脱敏。
7. 对禁止事项的自查声明：无 XIM/XTest/xdotool；无 `/opt` 安装；不覆盖系统 `/usr`；不在仓库或日志放置部署凭据。

材料不全时，验收负责人退回补充，状态记为“待验收”，不能推定通过。

## 3. 统一验收流程

1. **接收与范围检查**：核对任务范围、文件所有权、提交号、接口版本和材料完整性；检查敏感信息及越界文件。
2. **可复现构建**：在干净工作目录按文档构建，记录系统、编译器、fcitx5/API 版本、命令和结果。不得仅依赖开发者本机已有缓存。
3. **任务级测试复核**：验收负责人独立运行任务规定的自动化测试；抽查关键边界和失败路径。测试失败时记缺陷并退回负责者。
4. **接口与组合验证**：确认核心、字典导入器/loader、addon、配置之间只通过冻结接口交互；用同一份合法 fixture 交叉验证导入和查询结果。
5. **安全与部署审计**：检查安装清单和脚本在临时 HOME/DESTDIR 下运行；确认不会写入 `/usr` 或 `/opt`，凭据不在源代码、历史、日志、产物中；验证卸载只移除本项目登记文件。
6. **Wayland 端到端验收**：在目标机真实 Wayland 会话安装用户级构建，确认 addon 注册且在实际应用里完成第 4 节全部行为。X11、模拟器或纯 C API 结果不能替代此项。
7. **回滚与旧环境保护**：执行卸载/回滚，确认原用户级状态恢复、旧输入法仍可选择，系统文件无本项目改动。
8. **结论归档**：由同一验收负责人更新验收记录，填写逐项结果、证据路径、缺陷编号、遗留风险和结论；发布/交接前复核全部任务都已有结论。

## 4. 最终验收清单

### 4.1 项目和交付完整性

- [ ] A0–A5 各任务均有负责人、提交号、接口版本和独立验收结论。
- [ ] 每个任务的代码、文档、测试及复现命令齐全，且已由统一验收负责人复核。
- [ ] 主干/集成版本可在干净环境构建；测试结果可复现。
- [ ] 所有接口版本一致；Rime 导入器产物可由运行时 loader 读取，端到端查询词条正确。
- [ ] 变更无未批准的跨任务文件冲突；遗留缺陷和限制明确列出。

### 4.2 行为验收

- [ ] 中文模式输入字母时，应用中显示正确 preedit；缓冲只由引擎单点持有。
- [ ] 候选显示数量及排序符合配置/契约，首期默认页大小为 9。
- [ ] 数字选择、空格选择、翻页和候选页边界行为正确；候选无效时不丢失输入。
- [ ] Enter 提交原始缓冲；退格逐字删除；Esc 清空且不提交。
- [ ] 中英文切换、英文态按键转发、非处理键、焦点切换和输入法停用行为符合已冻结策略。
- [ ] 每个输入字符最终被提交、留在 preedit 或由明确的取消行为移除；无静默丢键/丢字符。
- [ ] 至少在目标机实际 Wayland 会话的一个真实应用中完成上述用例；记录应用和 toolkit。

### 4.3 Rime 词库兼容

- [ ] 对支持的 rime-ice 词库样本解析成功，字段、编码、权重、注释/转义规则符合测试夹具。
- [ ] 导入统计准确；坏行和不支持语法有可定位错误，绝不静默吞掉。
- [ ] 相同输入重复编译得到确定性索引；索引版本、完整性及损坏处理测试通过。
- [ ] 查询结果、编码前缀和候选权重与输入词库一致；文档清楚说明 Lua 动态逻辑不在首期兼容承诺内。
- [ ] 未将完整第三方词库或未获授权数据复制进仓库。

### 4.4 部署、安全与回滚

- [ ] 目标机身份按项目文档确认；凭据仅从仓库外私密资料读取，不回显、不落盘到日志。
- [ ] 安装路径全部在用户目录或项目隔离前缀；审计确认 `/usr` 和 `/opt` 未被本项目写入。
- [ ] 安装、重复安装、卸载、回滚在隔离测试路径通过；只操作本项目清单管理的文件。
- [ ] 日志、文档、提交历史和构建产物无密码、token、私钥或真实用户输入。
- [ ] 回滚后旧输入法仍可用；新 addon 可停用/移除，用户原配置已恢复。

## 5. 结论定义

- **通过**：强制清单全部通过；无阻断缺陷；证据已归档，回滚成功。
- **有条件通过**：无安全、数据丢失或基本输入阻断问题；仅有非关键缺陷/明确限制。必须列出责任人、期限、风险接受人；不得据此宣称全部验收完成或作为正式发布依据，除非项目负责人明确批准。
- **不通过**：任一强制项失败、关键证据缺失、无法复现、存在系统路径越界/凭据泄漏，或 Wayland 端到端用例未通过。修复后重新执行受影响的任务级及集成验收。

## 6. 验收记录最小字段

在 `docs/验收记录.md` 为每次验收填写：验收负责人、日期、验收提交号、任务/模块、接口版本、环境、执行命令、通过/失败项目、证据和脱敏日志路径、缺陷链接、遗留风险、回滚结果、最终结论及复核人（如有）。
