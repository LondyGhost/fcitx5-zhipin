# Linux 智能 ABC：独立 fcitx5 引擎整体方案

## 1. 目标与边界

实现一个可在 Linux 桌面使用的独立 fcitx5 输入法引擎，提供 ABC 风格字母输入缓冲、候选查询/翻页/选择、预编辑显示、提交和中英文切换。引擎拥有完整输入状态，不借助 fcitx5-rime 私有状态，不通过模拟键盘绕过输入法协议。

硬性边界：

1. 使用 fcitx5 原生 addon/输入法引擎 API；Wayland 客户端支持由 fcitx5 输入法通路完成。禁止 XIM、XTest、xdotool 及向应用注入模拟按键。
2. 不改写系统 `/usr` 下文件，不安装到 `/opt`。部署采用用户级目录或项目隔离前缀，并提供可逆卸载/回滚。
3. Rime 词库是数据兼容来源，不要求运行时依赖 librime 或执行 Rime Lua/Processor。首期支持 rime-ice 实际使用的词库格式或明确的离线转换格式。
4. 旧 `abc_buffer`/librime 方案仅作行为参照、词条对照和回归基线；不得作为最终可见缓冲实现。
5. 所有源文件、文档、测试、脚本、日志及构建产物归档于 `D:\workbuddy\linux智能ABC`。部署凭据不得进入仓库。

## 2. 当前已知事实与基线

此前目标机已构建隔离前缀的 librime 1.17.0、外部 `rime-abcabbr.so`、独立 fcitx5-rime addon 和 rime-ice 词库。C API 行为测试确认：字母暂存、空格确认、9 个候选、空格选择首候选、回车原文上屏、退格、Esc、Shift 等旧方案行为可用。但暂存期间 `RimeContext.composition.length == 0`，fcitx5-rime 前端无法显示插件私有缓冲。因此必须由新引擎自行持有缓冲并产生 preedit。

词库实际表路径包括 `cn_dicts/8105`、`cn_dicts/base`、`cn_dicts/ext`、`cn_dicts/others`、`cn_dicts/tencent`。rime-ice 方案包含 Lua Processor/Translator；新引擎不依赖这些运行时代码。导入器应探测并记录实际输入文件格式、编码、字段、注释及转义规则，不能假设文件名为 `rime_ice.base`。

## 3. 建议架构

```text
应用 (Wayland / X11)
  ⇅ fcitx5 原生输入法协议（由 fcitx5 处理）
fcitx5
  └─ ABC addon / InputMethodEngine
       ├─ Key adapter：fcitx5 KeyEvent 与引擎按键命令转换
       ├─ Engine state：模式、缓冲、候选页、焦点会话状态
       ├─ Candidate service：前缀匹配、排序、分页、选择
       ├─ Dictionary provider：只读索引接口
       ├─ Rime importer/compiler：离线词库解析和规范化索引生成
       └─ Config：用户配置、热键、用户词条路径
```

建议先实现纯 C++ 核心库（不依赖 fcitx5），再由 addon 做薄适配。核心库的数据类型和接口在任务并行前冻结，具体签名见第 8 节。UI/preedit/candidate list 的生命周期必须符合所选 fcitx5 API 版本；版本差异集中在 addon 适配层，不泄漏到核心状态机。

## 4. 模块职责

### 4.1 fcitx5 addon

注册引擎、接收按键事件、读取配置、创建核心会话、将核心快照映射为 fcitx5 preedit/candidate list，并调用 fcitx5 commit/preedit 接口。addon 不解析词库，不实现匹配算法，不维护第二份缓冲。需要确认目标机 fcitx5 开发包/API 版本后锁定 CMake 依赖与 ABI。

### 4.2 输入核心

纯逻辑状态机，不直接依赖 GUI、fcitx5 或文件系统。每个输入上下文拥有独立会话；外部以事件驱动，输出明确的副作用命令（更新预编辑、候选、提交、清除等）。状态快照不可暴露可变内部容器。

### 4.3 候选服务

通过只读字典接口按编码前缀检索词条，统一排序、去重、候选分页和选择索引。初版以确定性排序为主：词频降序、稳定的词条/来源次序作平局规则；实现不得依赖导入文件的偶然遍历顺序。后续可增加用户词频，但需保持接口兼容。

### 4.4 词库导入与索引

离线工具负责解析支持的 Rime 文本词库（如 YAML/TXT 表，具体格式以样本和测试确认），处理 UTF-8、BOM、注释、转义、权重/词频及无效行，并输出版本化、可校验的引擎索引。至少保留 phrase、code、weight、source/ordinal；导入报告列出输入文件、有效/跳过行数、编码错误和重复数。对不支持的 Rime 语法明确报错，不能静默丢数据。词库导入不执行 Lua，也不把 schema 中的 Processor 当成词条数据。

### 4.5 配置和部署

配置至少涵盖默认中/英文模式、候选页大小（默认 9）、用户词库/索引路径、切换热键及缓冲行为。提供用户级 addon 安装、环境/缓存刷新说明、验证、卸载及回滚。脚本不得含明文密码；目标机执行的日志必须脱敏。

## 5. 输入状态与按键行为

基线状态：`Disabled/English`、`ChineseEmpty`、`Composing`、`Selecting`。模式和组合状态应以可验证的不变量建模，而非用多个互相矛盾的布尔值。

建议转移：

| 当前状态 | 输入 | 动作/下一状态 |
|---|---|---|
| English | 普通键 | 不消费，交给应用 |
| ChineseEmpty | a-z/A-Z | 规范化后加入缓冲，显示原始/规范化 preedit，进入 Composing |
| Composing | a-z/A-Z | 加入缓冲并刷新候选 |
| Composing | Backspace | 删除一个编码字符；空缓冲则清除组合并回 ChineseEmpty |
| Composing | Space | 有候选时进入候选选择；无候选时按配置策略保留缓冲或提交原文，默认不吞掉数据 |
| Selecting | 数字 1-9 | 选择当前页对应候选并提交；无对应项时按配置/按键转发规则处理 |
| Selecting | Space | 选择当前页首候选；无候选则不丢失输入 |
| Selecting | PageUp/PageDown | 翻页并更新候选页/高亮 |
| Composing/Selecting | Enter | 提交原始缓冲，不提交猜测候选；清空组合 |
| 任意组合态 | Esc | 清空组合，不向应用提交 |
| 任意组合态 | 非处理键（标点、光标等） | 按明确策略提交原文或先结束组合，再让 fcitx5 决定是否转发；不得静默丢键 |
| 任意中文态 | 切换热键 | 清理或保留组合按配置执行，切至英文；反向切换至中文 |

以上为初始基线；实现任务开始前将未确定的标点、无候选空格、大小写、按键转发规则固化成核心用例。字符缓冲限制必须有上限和溢出策略。所有路径保证每个输入字符最终被提交、保留在 preedit 或明确取消，不能无声丢失。

## 6. fcitx5 / Wayland 集成

addon 按目标机安装的 fcitx5 headers 示例实现并通过 fcitx5 原生引擎注册。每个按键处理要正确返回是否消费；commit 与 preedit 的更新顺序、焦点丢失、输入法停用、应用切换时清理行为需由集成测试验证。Wayland 兼容不是自行实现 Wayland text-input 协议，而是运行于 fcitx5 框架提供的协议桥接中。不得假定 X11 测试通过即可证明 Wayland 可用，必须在目标机真实 Wayland 会话中测量。

## 7. 非功能要求

- 核心和导入器有自动化测试；相同输入数据重复编译得到确定性索引。
- 索引含 magic、格式版本、字节序/编码约定、记录数及完整性校验；损坏或不兼容时给出错误，不崩溃、不覆盖有效索引。
- 文件解析和索引加载对异常输入有界，不执行词库内容；路径和输出采用显式参数。
- 诊断默认不记录用户输入文本；如测试记录必须脱敏并征得数据所有者授权。
- CMake 构建支持目标 Linux 环境；依赖、API/ABI 版本和构建命令记录在项目文档。

## 8. 并行开发接口冻结建议

以下为边界约定，实际类型签名由任务 A0 输出 `docs/interfaces/` 接口契约并经集成负责人确认后冻结：

```text
EngineSession::handle(KeyCommand) -> EngineResult
EngineResult = { consumed, mode, preedit, candidates, page, highlighted, effects }
Dictionary::lookup(prefix, limit, offset) -> CandidateBatch
Candidate = { text, code, weight, source, stable_id }
DictionaryCompiler::compile(inputs, output, options) -> ImportReport
```

`EngineSession` 是缓冲和状态的唯一所有者。`Dictionary` 只读、线程安全或明确标注线程约束。`DictionaryCompiler` 是离线工具，输出格式版本必须与运行时 loader 的接口契约一致。addon 只依赖核心公开头文件；核心不能反向依赖 addon。共享接口文件仅由任务 A0/集成负责人维护；并行任务不得自行改接口或编辑对方模块文件。

## 9. 构建、部署、验收和回滚

1. 在本地仓库审查接口和单元测试，使用 Linux 目标机或兼容构建环境构建；所有命令、依赖版本、提交号记入脱敏日志。
2. 安装到用户级目录/项目隔离前缀，addon 搜索路径以用户会话配置为准，不覆盖系统文件。先备份已有同名用户级配置/文件。
3. 刷新 fcitx5 addon 缓存或按目标版本的安全流程重启用户级 fcitx5；核对新引擎已注册。
4. 在 Wayland 会话测试：输入缓冲可见、候选页显示/翻页、候选提交、原文 Enter、退格、Esc、英文切换、焦点切换、目标应用兼容性及非处理键转发。
5. 验证安装文件均在允许目录；`/usr`、`/opt` 无本项目改动；旧输入法仍可选择。
6. 回滚时停用新 addon、移除本项目用户级安装并恢复此前备份；不触碰系统文件。

验收细项记录在 `docs/验收记录.md`，构建产物、脚本和脱敏日志分别放在 `artifacts/`、`scripts/`、`logs/`。

## 10. 风险与待验证项

- Rime 字典文件可能因版本/来源采用不同字段、编码或转义；用真实样本编写 golden tests 后冻结首期支持子集。
- rime-ice 的 Lua translator/processor 行为不能仅靠纯词库复现；首期明确承诺词条和编码兼容，不承诺 Lua 动态逻辑等价。
- fcitx5 API/ABI 随发行版版本变化；以目标机版本为准并将适配限制在 addon 边界。
- 目标机 Wayland 桌面、应用 toolkit 和会话配置尚须实测；不能将 C API/旧插件测试作为新引擎验收。
- 大词库索引大小、冷启动时间和查询延迟需在真实词库上测量，再决定 mmap、压缩或分片；首版避免过早优化。
