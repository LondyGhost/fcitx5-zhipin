# 独立引擎并行开发任务拆分

## 0. 共通规则

所有任务必须遵循 [`独立引擎整体方案.md`](独立引擎整体方案.md)。项目唯一交接根目录为 `D:\workbuddy\linux智能ABC`。未完成 A0 接口冻结前，只能各自在任务目录开发，不得并行改共享接口。每项任务须提交代码、测试、运行说明和自检结果；禁止提交部署凭据、未经审查的用户数据、明文输入日志。不得修改 `/usr` 或 `/opt`，不得使用 XIM/XTest/xdotool。每个任务按下文文件所有权工作；跨任务改动通过新增适配文件或先由集成负责人协调，不能直接修改另一任务的文件。

每项任务的自测和交付材料完成后，**由同一位指定的集成验收负责人统一汇总验收**，负责独立复跑测试、接口组合、Wayland 端到端验证、部署安全审计和回滚，并在验收记录中给出结论。具体流程、强制清单和通过/不通过定义见 [`独立任务验收标准.md`](独立任务验收标准.md)。模块作者自测通过不能替代统一验收。

建议分支/工作目录独立，合并由集成负责人执行。公共头文件、根构建清单、README、整体方案和任务文档只由集成负责人修改，除非某 task 明确拥有对应文件。

每项任务已拆成可独立分发的 Markdown，入口见 [`../tasks/README.md`](../tasks/README.md)。每份任务书均包含该任务的输入、输出/文件所有权、接口边界、硬性要求、验收标准及依赖关系；分发任务时应同时提供整体方案和通用验收标准链接。

## A0 — 接口契约与构建骨架（先行，集成负责人）

- **输入**：整体方案第 3、8 节；目标 Linux 的 fcitx5/CMake 版本信息；下游任务需求。
- **输出/文件所有权**：`docs/interfaces/**`、`docs/目标机环境.md`、根 `CMakeLists.txt`、公共 `source/include/abc/**`、空模块目录及接口冒烟测试。
- **接口边界**：定义 `KeyCommand`、`EngineResult`、`Candidate`、`CandidateBatch`、`Dictionary`、session 工厂、索引格式版本及 addon/core 依赖方向；公共类型由本任务单点维护。
- **硬性要求**：纯核心接口不依赖 fcitx5；词库 provider 只读；结果明确包含 consumed/effects；索引格式版本策略及字符编码明确；构建骨架允许模块独立加入。
- **验收标准**：接口文档含字段语义、生命周期、错误策略和示例；Linux 上空骨架 configure/build/test 通过；下游各任务书面确认接口后冻结并标版本。
- **依赖/并行**：必须先于 A1-A5。完成冻结后公共接口只接受集成负责人变更。

## A1 — 输入状态机核心

- **输入**：冻结的 `docs/interfaces/engine.md` 与核心公共头文件；整体方案第 5 节按键基线。
- **输出/所有权**：`source/core/**`、`tests/core/**`、`docs/modules/core.md`。不得修改公共头文件或 addon/词库文件。
- **接口边界**：实现 `EngineSession::handle(KeyCommand)`，输出不可变快照/命令；不读文件、不访问 fcitx5、不查询具体词库格式，通过注入的 `Dictionary` 抽象查询。
- **硬性要求**：唯一拥有输入缓冲；明确每个状态转移；Enter 原文提交，Esc 清空，退格逐字符删除；候选空/页边界/无效数字不丢数据；英文态未处理按键不消费；无隐藏全局状态。
- **验收标准**：覆盖方案按键表及边界/异常事件的单元测试；可用 fake Dictionary 测试；测试验证字符不静默丢失、候选高亮/页码一致；核心独立构建通过。
- **依赖/并行**：A0 冻结后开始；可与 A2-A5 并行。

## A2 — Rime 词库解析与索引编译器

- **输入**：冻结的 `docs/interfaces/dictionary.md`、索引格式契约；经许可且脱敏/可公开的 rime-ice 词库样本及其格式说明。
- **输出/所有权**：`source/dict-importer/**`、`tests/dict-importer/**`、`docs/modules/rime-import.md`。不得修改 runtime dictionary、公共接口和词库原始数据。
- **接口边界**：命令行离线工具读取显式输入路径，生成契约规定的索引与 `ImportReport`；输出供 A3 loader 消费。
- **硬性要求**：UTF-8/BOM、注释、字段、权重、转义和坏行策略有测试；明确拒绝不支持语法，不执行 Lua；稳定排序/去重；原始词库不复制进 Git，测试样本须合法且最小化。
- **验收标准**：golden fixtures 生成可重复字节输出；损坏输入给出非零退出及定位信息；报告统计有效/跳过/重复记录；大文件流式或有明确内存上限；命令帮助和示例齐全。
- **依赖/并行**：A0 格式契约冻结后开始；可与 A1、A3、A4、A5 并行。

## A3 — 运行时字典与候选检索

- **输入**：A0 冻结的 Dictionary/index contract；A2 的格式说明及由集成测试提供的 fixture。
- **输出/所有权**：`source/dictionary/**`、`tests/dictionary/**`、`docs/modules/dictionary-runtime.md`。不得修改 importer、核心状态机或公共接口。
- **接口边界**：实现只读索引 loader 和 `Dictionary::lookup`；候选稳定 ID、分页、排序行为符合契约；错误通过接口返回，不终止进程。
- **硬性要求**：验证 magic/version/长度/完整性；拒绝越界/截断/恶意记录；查询确定性；并发约束写入文档；加载失败不覆盖有效数据且不崩溃。
- **验收标准**：用独立手工构造索引和 A2 fixture 测试精确查询、无结果、重复、分页、损坏文件及版本不兼容；性能基准报告注明设备和数据规模。
- **依赖/并行**：A0 后可并行开发；和 A2 集成需共同通过共享 fixture，但不得改对方文件。

## A4 — fcitx5 addon 适配层

- **输入**：A0 addon 接口契约、目标机 fcitx5 API/ABI 版本；A1 输出映射文档/可链接核心接口。
- **输出/所有权**：`source/fcitx5-addon/**`、`tests/fcitx5-addon/**`、`docs/modules/fcitx5-addon.md`、用户级安装模板 `deploy/fcitx5-addon/**`。不得修改 core/dictionary/common headers/根构建文件。
- **接口边界**：将 fcitx5 KeyEvent 转成 `KeyCommand`，调用 session，将结果映射为 fcitx5 preedit/candidate/commit；不实现缓冲或候选排序。
- **硬性要求**：原生 addon/API；Wayland 由 fcitx5 协议路径承载；无 XIM/XTest/xdotool；按键 consumed 语义正确；会话/焦点生命周期安全；所有安装目标均用户级或隔离前缀。
- **验收标准**：目标版本编译、addon 注册/发现；模拟或集成测试覆盖 preedit 更新、commit、停用清理；真实 Wayland 验收由 A6 完成；安装清单证明未写 `/usr`、`/opt`。
- **依赖/并行**：A0 后可搭建适配框架；与 A1 联调需 A1 接口实现可用；可与 A2/A3/A5 并行。

## A5 — 配置、用户词条与安装/回滚脚本

- **输入**：整体方案配置/部署要求；A0 配置契约及 A4 用户级安装布局。
- **输出/所有权**：`source/config/**`（如配置需要运行时解析）、`scripts/build-*.sh`、`scripts/install-user.sh`、`scripts/uninstall-user.sh`、`deploy/**`、`tests/deploy/**`、`docs/modules/deployment.md`。不得修改 addon 实现、根 CMake 或凭据文件。
- **接口边界**：脚本通过显式参数/环境变量获取前缀与构建目录；只管理本项目标记的用户级文件；配置 schema 交给 addon/core 消费。
- **硬性要求**：不含密码/token；不写 `/opt`、系统 `/usr`；安装前检查冲突并备份；卸载仅删除自身清单登记的文件；日志脱敏；失败安全退出。
- **验收标准**：临时 HOME/DESTDIR 中可重复安装、验证、卸载并还原；路径含空格可工作；权限/缺文件/重复安装测试通过；shellcheck 或等效静态检查通过（若工具可用）。
- **依赖/并行**：A0 安装契约确认后并行；A4 路径未定时使用临时 DESTDIR，不修改其文件。

## A6 — 集成、Wayland 验收与发布归档（集成负责人）

- **输入**：A1-A5 合并版本、目标机环境文档、验收记录模板及目标机授权访问方式。
- **输出/所有权**：`tests/integration/**`、`tests/manual/**`、`docs/验收记录.md`、`artifacts/manifest.md`、脱敏 `logs/**`；如需修复模块代码，退回对应任务 owner 或由集成负责人单独协调。
- **接口边界**：负责模块组合、端到端测试、目标机用户级部署、验收记录与回滚演练；不私自改变模块契约。
- **硬性要求**：目标机 `192.168.1.250:47672`；凭据仅读取本地私密文件，不打印/提交；不得改 `/usr`、`/opt`；确认 Wayland 会话；所有日志脱敏。
- **验收标准**：真实 Wayland 应用完成可见缓冲、候选、翻页/选择、原文 Enter、退格、Esc、中英文切换、焦点切换和按键转发；确认旧输入法可用；安装路径审计、回滚成功；记录提交号、环境和通过/失败结果。
- **依赖/并行**：A1-A5 集成后执行。测试发现问题建明确缺陷并交回 owner 修复，避免在集成阶段形成未经审查的重叠改动。

## 任务交付模板

每项交付附：变更文件清单、接口版本、构建/测试命令及结果、已知限制、是否触碰目标机、日志/产物路径。任务完成定义为可由另一人仅依 README 和模块文档复现，而非仅“代码已写”。

## 并行关系概览

```text
A0 接口/骨架
 ├─ A1 核心状态机 ──────────────┐
 ├─ A2 导入器 ── A3 运行时字典 ├─ A6 集成与 Wayland 验收
 ├─ A4 fcitx5 addon ────────────┤
 └─ A5 配置/部署脚本 ──────────┘
```

A2 与 A3 可并行先做 parser/loader 的内部实现，但共享索引布局以 A0 契约为准；使用各自私有 fixture，契约冻结后再交叉验证。禁止不同任务同时编辑同一文件。
