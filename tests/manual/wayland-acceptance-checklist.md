# Wayland 端到端手工验收清单（A6 拥有）

> 本清单是最终验收的强制执行规程（`docs/独立任务验收标准.md` 3.6、4.2）。
> **前置条件未满足前不得执行**：A2 索引导入器、A3 运行时词典、A4 fcitx5 addon
> 均已提交交付，用户级安装完成，且新输入法已在 fcitx5 中注册可选。
> X11、模拟器、纯 C API 或单元测试结果**不能替代**本清单的任何一行。

## 3. 用例表（逐项在两个主应用中执行；每项记录：预期 / 实际 / 证据路径 / 结果）

> 证据：截图或录屏存 `logs/a6/manual-evidence/`（文件名 `UCnn-<应用代号>.png`），
> 内容只含测试输入，不得包含真实用户数据。

### 3.1 缓冲与预编辑

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| UC01 | 中文态字母可见 preedit | 切至新输入法中文态，键入 `nihao` | 应用内显示 preedit `nihao`（客户侧 preedit 按 `preeditInClient`） |
| UC02 | 大写规范化 | 键入 `NiHao` | preedit 显示 `nihao` |
| UC03 | 缓冲上限 | 键入 >64 个字母 | 前 64 个留在 preedit；第 65 个起直接出现在应用文本中（不丢失、组合保持） |

### 3.2 候选显示与选择

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| UC04 | 候选窗显示 | `nihao` 后按空格 | 候选窗出现，≤9 项，页码 1/3（以词库为准），首项高亮 |
| UC05 | 数字选词 | 候选态按 `2` | 第 2 项候选上屏，候选窗与 preedit 清除 |
| UC06 | 空格选词 | 重新组合后按空格、再按空格 | 第一步进入选择（窗保持），第二步提交页首候选 |
| UC07 | 翻页 | 候选态按 PageDown/PageUp | 页码与候选集随之更新，高亮回到新页首；末页/首页再翻无变化 |
| UC08 | 无效数字 | 候选不足时按无对应数字 | 键转发到应用或无操作（按契约不丢缓冲）；组合仍在，可继续选择 |

### 3.3 提交与取消

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| UC09 | Enter 原文提交 | 键入 `nihao` 后按 Enter | 应用出现原文 `nihao`（非候选词） |
| UC10 | Backspace | 键入 `nihao` 后按 3 次退格 | preedit 逐字符缩短至 `ni`；再退格删除应用已有文本 |
| UC11 | Esc 取消 | 键入任意编码按 Esc | preedit 与候选窗清除，应用无文本插入 |

### 3.4 模式与转发

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| UC12 | 中英切换 | 组合中按切换热键（默认 Shift） | 按策略提交原文或清除；此后字母直接进入应用（英文直通） |
| UC13 | 英文态转发 | 英文态键入字母/数字/标点/Enter | 全部原样进入应用，无 preedit |
| UC14 | 非处理键转发 | 组合中按方向键、Tab、标点 | 原文按策略先提交（或按冻结策略清除），随后按键转发给应用生效；无按键消失 |
| UC15 | 焦点切换 | 组合中切换到另一应用 | 旧应用无残留 preedit；新应用可立即输入；`reset()` 语义生效 |

### 3.5 安装、回滚与旧输入法保护（在 A4+A5 交付后于目标机执行）

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| UC16 | 用户级安装 | `install-user.sh`（A5 交付后） | 仅写 `$HOME`；清单登记；重复安装幂等；已有用户配置不被覆盖 |
| UC17 | 安装审计 | 对照清单逐文件核对 | 无 `/usr`、`/opt` 写入；权限合理 |
| UC18 | 卸载/回滚 | `uninstall-user.sh` | 清单登记文件全部移除；配置模板如用户未改动则移除、已改动则按脚本策略保留并告知；**历史 abcabbr 试验文件与 fcitx5-chinese-addons 完好** |
| UC19 | 回滚后旧输入法 | 卸载后选择拼音输入 | 旧输入法仍可正常输入 |
| UC20 | 重装复验 | 再次安装并抽测 UC01/UC04/UC09 | 行为与首装一致 |

## 4. 结果记录规则

- 每用例结论 ∈ {通过, 失败, 阻塞}；失败/阻塞必须附证据与最小复现步骤。
- 任一 3.1–3.4 用例失败 → 集成验收不得为“通过”。
- 3.5 全部通过且 3.1–3.4 通过 → 方可给出“通过”；仅有非关键缺陷可给“有条件通过”
  （须列责任人、期限、风险接受人，见验收标准 §5）。
- 执行完成后由 A6 在 `docs/验收记录.md` 的 Wayland 手工用例表逐行回填并引用本清单版本。
